# dsh-wiki-rag 对标研究报告（2026-11-04 第一批）

> 范围：从 Notion / Obsidian / Logseq / 思源笔记（SiYuan）/ 语雀 / 飞书文档 / Anytype / Roam / Tana / Mem 中挑选与本插件（DSH 内嵌知识库面板，文件树 + 富文本编辑器 + RAG 检索，服务高校行政/文档管理）最相关的 5 个做深对比。
> 本插件现状基线：`bundle/src/client/index.tsx`（约 2480 行单文件 React），侧栏宽 260px，文件树 + 搜索框 + 状态筛选，右侧 Tiptap 富文本编辑器，设置/历史版本/日志面板。
> 输出：5 维度深对比 + 可执行优化项清单 O-xx（≥15 条）。

## 1. 维度 A：信息架构（文件树 vs 双向链接 vs 块结构）

### 1.1 各产品做法

| 产品 | 导航主结构 | 检索入口 | 双向链接/反链 |
|---|---|---|---|
| Obsidian | 文件树（侧栏）+ 标签 + 图谱 | Ctrl+P Quick Switcher（模糊文件名）、Ctrl+Shift+F 全局搜索、命令面板 Ctrl+P | `[[wikilink]]`，反链面板显示"谁引用了我" |
| 思源 | 文件树 + 块树（文档内块可折叠） | Ctrl+P 命令面板、全局搜索、SQL 查询嵌入 | 块级双向链接 `((block-id))`，反链面板可过滤/搜索 |
| Notion | 侧边栏页面树 + 数据库 | Ctrl+P / Ctrl+K 搜索（页面 + 块内容）、Ctrl+[ 后退 | `@mention` 页面引用，backlinks 自动列出 |
| Logseq | 大纲 outliner（无传统文件树，按页/日记组织） | Ctrl+K 快速切换页、Ctrl+Shift+P 命令面板 | 页级 + 块级双向链接，linked references 自动聚合 |
| 飞书文档 | 知识库空间树 + 文档内左侧自动目录（TOC） | Ctrl+J 全局搜索、文档内查找 | 文档间 `[[链接]]`，知识库内关联文档面板 |

### 1.2 共同最佳实践

1. **三入口并行**：文件树（浏览）+ 命令面板/快速切换（直达）+ 全局搜索（检索内容）。Obsidian / Logseq / Notion 都把 Ctrl+P 作为高频入口。Logseq 官方甚至把 "CMD-K to search" 作为新手三件套之一。
2. **当前文档自动定位**：Obsidian File Explorer 有"Automatically reveal active file"开关，切文档时自动滚动到树中并高亮；飞书文档左侧目录也会随滚动自动高亮当前章节。
3. **文档内 TOC**：飞书 / Notion / 思源都在长文档左侧自动生成大纲目录，点击跳转；飞书支持按标题层级筛选（H1/H2/H3，可 1–9 级），目录可一键折叠隐藏。
4. **收藏 + 最近打开**：所有产品都有星标收藏与最近文档列表，作为文件树之外的快速通道；Notion 把"Recent"放在 Ctrl+P 面板首屏。
5. **反链/引用面板**：思源 / Obsidian / Logseq 在文档底部或右侧显示"谁引用了我"，是 RAG 溯源的天然 UI 容器；思源反链面板还支持过滤与搜索。
6. **面包屑路径**：Notion / 飞书文档顶部都显示"空间 / 父文件夹 / 当前文档"面包屑，用户随时知道自己在哪。
7. **新建入口永远可达**：Notion 侧栏底部有"+ New page"；Obsidian 文件树顶部 hover 出现新建按钮；飞书知识库顶部有"新建"。本插件的 + 菜单已收敛到搜索框旁（index.tsx:1551），是优点但未做 hover 显隐。

### 1.3 本插件差距

- **G-A1**：只有文件树 + 搜索框两个入口，**无命令面板**；用户想打开某文档必须先记得它在哪个文件夹。Ctrl+P 在 Notion/Obsidian/Logseq 都是最高频快捷键。
- **G-A2**：文件树无"自动定位当前文档"——从最近/收藏打开文档后，树中不滚动、不高亮（已有 `scrollToFileId` 但无 flash 动画，见 UX-SPEC A-09）。
- **G-A3**：长文档无文档内大纲 TOC；高校行政文档动辄几十页，用户无法快速跳章节。飞书 TOC 是企业文档用户的肌肉记忆。
- **G-A4**：无反链/引用面板；RAG 检索到的片段无法反查"这个片段被哪些文档引用"。思源块级反链是 RAG 溯源的最佳参照。
- **G-A5**：收藏/最近打开条目视觉与文件树行脱节（UX-SPEC A-11 已列）。
- **G-A6**：无面包屑路径；打开深层文档后，用户不知道它在哪个文件夹下（只能靠文件树高亮反推）。
- **G-A7**：新建入口 + 菜单常驻显示，未做 hover 显隐；Obsidian 是 hover 文件树顶部才出现新建按钮组。

## 2. 维度 B：编辑体验（快捷键 / 斜杠命令 / Markdown 手感 / 大纲折叠 / 块拖动 / 双链）

### 2.1 各产品做法

| 产品 | 斜杠命令 | 快捷键体系 | 块拖动 | 双链输入 |
|---|---|---|---|---|
| Obsidian | 无斜杠命令（用 `##`/`-` 语法触发） | 高度可自定义，社区插件扩展 | 行级拖动 | `[[` 触发补全 |
| 思源 | `Ctrl+/` 块标菜单（块级操作） | 全部可自定义（见快捷键表） | 块级拖动 | `((` 块引用、`[[` 页引用 |
| Notion | `/` 触发 50+ 块类型菜单，输入过滤，Esc 关闭 | 固定体系，Ctrl+B/I/U/E | 左侧 ⋮⋮ 把手拖动 | `@` 触发 mention |
| Logseq | `/` 触发块菜单（任务/标题/代码块/计算器/日期/标注） | Cmd+Shift+↑↓ 移块，Enter 新块 | 大纲层级缩进拖动 | `[[` 触发页补全 |
| 飞书文档 | `/` 触发块菜单（标题/待办/表格/分割线/图片） | 企业级固定，Ctrl+B/I/U | 段落左侧 ⋮⋮ 把手 | `[[` 触发文档补全 |

### 2.2 共同最佳实践

1. **斜杠命令是块创建主入口**：Notion / Logseq / 飞书都在空行或行首输入 `/` 弹出块类型菜单，输入关键词过滤，↑↓ 选择，Enter 确认，Esc 关闭。Notion 有 50+ 块类型，Logseq 包括任务/标题/代码块/计算器/日期/标注/数学/附件。
2. **浮动工具栏在选区上方**：Notion / 飞书 / Tiptap 默认都是选中文字后在选区上方弹出格式条（B/I/U/链接/评论/AI）；位置在松开鼠标后 100–150ms 出现，避免拖选时闪烁。
3. **段落左侧把手**：Notion / 飞书悬停段落左侧显示 ⋮⋮，点击展开块操作菜单（转换类型/复制链接/删除/拖动/颜色标注）；思源是 `Ctrl+/` 触发块标菜单。
4. **Markdown 语法实时渲染**：Obsidian / 思源 / Typora 风格，输入 `#` 空格自动变 H1，`-` 空格自动变列表，`**` 自动加粗；Logseq 输入 `TODO` 自动变任务复选框。
5. **快捷键可自定义**：思源 / Obsidian / Logseq 都允许用户改键；Notion / 飞书固定但提供完整速查表。
6. **块拖动重排**：Notion / 飞书拖 ⋮⋮ 把手调整段落顺序；Logseq 用 Cmd+Shift+↑↓ 移动块；思源块级拖动不影响已有引用链接。
7. **双链补全**：Obsidian/思源/Logseq 输入 `[[` 触发文档名模糊补全；Notion 用 `@` mention；飞书用 `[[`。

### 2.3 本插件差距

- **G-B1**：无斜杠命令；用户要插入标题/列表/代码块必须先选中文本再点浮动工具栏，或记住 Markdown 语法。Notion 用户已被训练成"什么都用 / 做"。
- **G-B2**：浮动工具栏在 `onSelectionUpdate` 实时重渲染（UX-SPEC A-21 已列），拖选时闪烁。Notion 是 mouseup 后才出现。
- **G-B3**：段落左侧只有"样式标签 + ⋯"，无 ⋮⋮ 拖动把手；块无法拖动重排。Notion/飞书用户已习惯拖把手。
- **G-B4**：链接插入用原生 `prompt()`（UX-SPEC A-23 已列），与主题脱节。
- **G-B5**：无 `[[` 双链补全；高校行政文档间常互引（如"见《XX 办法》第 3 条"），目前只能贴 URL。
- **G-B6**：快捷键只有 Ctrl+S / Ctrl+F / `/`，无 Ctrl+B/I/U 等富文本快捷键；Notion 用户肌肉记忆是 Ctrl+B 加粗。
- **G-B7**：无 Markdown 实时语法渲染反馈（输入 `#` 空格不变 H1，必须手动选工具栏）。
- **G-B8**：浮动工具栏 15 个按钮横排，窄屏溢出（UX-SPEC A-24 已列）。

## 3. 维度 C：检索 / RAG 体验（全文搜索 / 语义问答 / 引用溯源 / 空结果引导）

### 3.1 各产品做法

| 产品 | 全文搜索 | 语义问答 | 引用溯源 |
|---|---|---|---|
| Obsidian | Ctrl+Shift+F，结果列表显示文件名 + 匹配行高亮 + 所在文件 | 无内置（社区 Smart Connections 插件） | 无 |
| 思源 | 全局搜索，结果按文档分组，匹配行高亮 | 无内置 | 块级反链面板 |
| Notion | Ctrl+P 搜索页面 + 块内容，结果显示面包屑路径 | Notion AI（答案 + "Sources" 侧栏列出引用文档） | 答案下方 Sources 列表，点击跳转 |
| Logseq | Ctrl+K 页切换 + 全局搜索块内容 | 无内置 | linked references 自动聚合 |
| 飞书文档 | Ctrl+J 全局搜索（文档 + 块 + 消息） | 飞书智能伙伴（答案 + 引用文档卡片） | 答案下方引用卡片，点击跳转原文 |

### 3.2 RAG 引用溯源的行业最佳实践（2026 模式）

1. **行内上标 `[1]`**：答案中每个事实后跟上标编号，学术引用模型，阅读最干净。Notion AI / 飞书智能伙伴都用这种模式。
2. **悬停预览**：鼠标移到 `[1]` 上弹出 1–2 行片段预览，不跳转；hover 延迟 200ms，避免误触。
3. **深链到段落**：点击引用跳到文档中具体段落并高亮该句（不是文档顶部）；这是内部知识库 RAG 的核心体验——用户要验证一句话，不是重读整个 PDF。
4. **侧栏来源面板**：Notion AI / 飞书智能伙伴都在答案右侧或下方列出所有来源文档卡片，可筛选/关闭低质量来源；每条来源显示文件名 + 匹配片段 + 相关度。
5. **空结果引导**：无结果时建议"试试更短关键词 / 检查拼写 / 导入新文档"；Notion AI 还会建议"换个问法"。
6. **流式输出**：答案逐字打出（streaming），不是等全部生成完才显示；Notion AI / 飞书都是流式。
7. **关键词搜索 vs 语义问答分层**：Obsidian/思源只有关键词搜索；Notion AI/飞书智能伙伴是问答式；本插件后端已有 `/api/wiki/search`（关键词 + score），但无问答端点。

### 3.3 本插件差距

- **G-C1**：搜索结果展示 `score 0.832` 技术字段（UX-SPEC A-15 已列），无命中词高亮，无面包屑路径。
- **G-C2**：无 ↑↓ 键盘导航（UX-SPEC A-16 已列）。
- **G-C3**：**无语义问答界面**——本插件有 RAG 后端（`/api/wiki/search`），但前端只有关键词搜索结果列表，没有"答案 + 引用溯源"的对话式呈现。这是本插件与 Notion AI / 飞书智能伙伴最大的差距。
- **G-C4**：搜索结果点击后打开文档，但不高亮命中片段（只是滚动到文档顶部）。Notion/飞书都会高亮命中词。
- **G-C5**：空结果只显示"无搜索结果"（UX-SPEC A-18 已列）。
- **G-C6**：搜索无历史记录；用户重复搜同一个词要重打。
- **G-C7**：无"在文档内查找"（Ctrl+F 浏览器原生）；长文档内定位关键词困难。

### 3.4 RAG 问答面板设计草案（O-05 落地参考）

右侧编辑器区顶部加 tab 切换：「编辑」|「问答」。问答 tab 布局：

```
┌─────────────────────────────────┐
│  问：如何接入？            [发送] │
├─────────────────────────────────┤
│  答：                            │
│  三步完成接入[1]：安装插件、      │
│  重启、使用。详见《接入指南》[2]  │
│                                 │
│  来源（2）：                     │
│  ┌──────────┐ ┌──────────┐     │
│  │接入指南   │ │API 参考   │     │
│  │三步...    │ │参数...    │     │
│  └──────────┘ └──────────┘     │
└─────────────────────────────────┘
```

- `[1]` 是上标链接，hover 弹出片段预览，点击深链到文档段落并高亮。
- 来源卡片 = 文件名 + 2 行片段 + 相关度色条。
- 流式输出：答案逐字打出，来源卡片在答案完成后淡入。
- 空状态：输入框下方建议"试试问：如何导入文件 / 支持哪些格式 / 如何备份"。

## 4. 维度 D：性能与可靠性（大库首屏 / 虚拟滚动 / 离线 / 版本备份 / 回收站）

### 4.1 各产品做法

| 产品 | 大库首屏 | 虚拟滚动 | 离线可用 | 版本/备份 |
|---|---|---|---|---|
| Obsidian | 本地文件，秒开 | 文件树虚拟滚动（1000+ 文件不卡） | 完全离线 | 文件历史（社区插件）+ Git |
| 思源 | 本地 SQLite，秒开 | 块树虚拟滚动 | 完全离线 | 数据快照 + 历史版本 + 回收站 |
| Notion | SaaS，首屏 1–2s | 虚拟滚动 | 离线缓存有限 | 页面历史（30 天）+ 回收站 |
| Logseq | 本地 Markdown，秒开 | 大纲虚拟滚动 | 完全离线 | Git 自动提交 |
| 飞书文档 | SaaS，首屏 1–2s | 虚拟滚动 | 离线缓存 | 历史版本（企业版）+ 回收站 |

### 4.2 共同最佳实践

1. **虚拟滚动是大库刚需**：Obsidian / 思源 / Notion 都对文件树和长列表做虚拟滚动，1000+ 行不卡。本插件已有虚拟滚动（`startIndex/endIndex`，index.tsx:1312），是优点。
2. **离线降级**：Obsidian / 思源完全离线；Notion / 飞书离线时显示缓存内容 + 顶部黄色横幅。本插件已有 offline state（UX-SPEC A-33 已列）。
3. **版本 + 回收站双保险**：思源 / Notion / 飞书都有历史版本 + 回收站；删除文档先进回收站，30 天后彻底删除。思源还支持数据快照（手动 + 自动）。
4. **自动保存**：所有产品都是静默自动保存（防抖 1–2s），不打断编辑；冲突时提示用户选择。本插件已有 900ms 防抖自动保存（index.tsx:1135）。
5. **骨架屏匹配真实布局**：Notion / 飞书首屏骨架是左右两栏，不是一堆灰条。
6. **导入进度可视化**：Notion 导入时右下角显示进度条 + 成功/失败计数；思源导入是任务队列。
7. **数据导出**：Obsidian 支持导出 MD/PDF；思源支持导出 zip；Notion 企业版支持批量导出。高校行政数据必须可导出。

### 4.3 本插件差距

- **G-D1**：删除文档是**直接删除**（`apiDelete` 无回收站），不可恢复；与思源/Notion/飞书的回收站机制差距大。高校文档误删是事故。
- **G-D2**：历史版本每文件只保留 3 个（index.tsx:1267 注释），且版本选择用 `<select>`，无日期分组（UX-SPEC A-48 已列）。
- **G-D3**：骨架屏只有左侧灰条，右侧编辑器区空白（UX-SPEC A-30 已列）。
- **G-D4**：导入进度条 total=0 时卡死（UX-SPEC A-34 已列）。
- **G-D5**：无数据导出/备份入口；高校行政数据不可导出是合规风险。
- **G-D6**：无导入任务队列；同时导入多个文件夹时只有一个 job state，后一个覆盖前一个。
- **G-D7**：无同步冲突的可视化对比（只有 409 时用 `window.confirm` 原生弹窗，index.tsx:1110）；思源/Notion 都有并排 diff 视图。

### 4.4 本插件已有优势（保持）

- **虚拟滚动已实现**：`startIndex/endIndex`（index.tsx:1312）对文件树做虚拟滚动，1000+ 文件不卡，这在同类内嵌插件中是优点。
- **自动保存防抖 900ms**：与 Notion（1s）/思源（即时）节奏接近，不打断编辑。
- **离线降级已有**：`offline` state + `__setOffline`（index.tsx:251），网络错误自动识别。
- **ErrorBoundary 已有**：渲染异常不白屏，可重试 3 次。

## 5. 维度 E：无障碍与国际化（aria / 键盘可达 / 快捷键自定义 / 中英双语 / 深浅主题）

### 5.1 各产品做法

| 产品 | aria/键盘 | 快捷键自定义 | 中英双语 | 深浅主题 |
|---|---|---|---|---|
| Obsidian | 基本 aria，键盘流强 | 完全可自定义 | 多语言 | 完全跟随 |
| 思源 | aria 完善，全部操作键盘可达 | 完全可自定义 | 中文原生，多语言 | 跟随系统 |
| Notion | aria 完善，菜单键盘导航 | 固定 | 多语言 | 跟随系统 |
| Logseq | 键盘流极致（Vim 模式） | 可自定义 | 多语言 | 跟随系统 |
| 飞书文档 | aria 完善，企业级 WCAG 合规 | 固定 | 中英双语切换 | 跟随系统 |

### 5.2 共同最佳实践

1. **菜单键盘可达**：Notion / 飞书 / 思源的右键菜单、斜杠菜单都支持 ↑↓Enter Esc。思源快捷键表覆盖所有操作。
2. **焦点环可见**：所有产品键盘 Tab 时显示 2px 焦点环；鼠标点击不显示。本插件宿主已有 `:focus-visible` 全局规则，但多个输入框 `outline: none` 把它禁了（UX-SPEC A-41 已列）。
3. **深浅主题跟随**：所有产品都 `@media (prefers-color-scheme)` 或手动切换。本插件用 `body[data-ds-dark-theme]`，令牌已双主题（好）。
4. **i18n**：本插件已有 `LOCAL_FALLBACK` 中英字典 + 宿主 `t()`（好），但大量 tooltip 硬编码中文（如"粗体"、"斜体"，index.tsx:1939–1948）。
5. **减少动效**：Notion / 思源都遵循 `prefers-reduced-motion`，系统开启后关闭动画。
6. **aria 标签**：飞书企业级 WCAG 合规，所有按钮有 `aria-label`，菜单有 `role="menu"`。

### 5.3 本插件差距

- **G-E1**：右键菜单 / + 菜单 / ⋯ 菜单无 `role="menu"` / `role="menuitem"`，无 ↑↓ 导航（UX-SPEC A-44 已列）。
- **G-E2**：浮动工具栏按钮 tooltip 硬编码中文（"粗体"/"斜体"），未走 i18n 字典。
- **G-E3**：快捷键不可自定义；高校行政用户可能需要改成熟悉的 Office 键位。
- **G-E4**：无 `prefers-reduced-motion` 适配（UX-SPEC A-46 已列）。
- **G-E5**：图标按钮无 `aria-label`；屏幕阅读器读不出来这是什么按钮。
- **G-E6**：Toast 无 `role="status"` / `aria-live="polite"`；屏幕阅读器不播报。

### 5.4 窄屏 / 移动端适配

| 产品 | 窄屏策略 |
|---|---|
| Obsidian | 侧栏可折叠为图标 rail，编辑器全屏 |
| 思源 | 侧栏抽屉式，手机端单栏 |
| Notion | 手机端侧栏变底部 tab，文档全屏 |
| Logseq | 手机端大纲单列 |
| 飞书文档 | 手机端目录变浮动按钮 |

本插件已有收起 rail 态（index.tsx:1287），但 rail 只有一个 WikiIcon，无 badge、无 tooltip（UX-SPEC A-51 已列）。窄屏（<768px）时左右分栏会挤压，浮动工具栏会溢出（UX-SPEC A-24 已列）。

## 7. 结论与实施建议

### 7.1 本插件定位

本插件是 **DSH 宿主内嵌的本地优先知识库面板**，核心场景是高校行政文档的导入、检索、编辑。它不需要做成 Notion 那样的块结构 SaaS，也不需要做成 Logseq 那样的 outliner；它的合理形态是 **Obsidian 风格的文件树 + 思源风格的块引用/RAG 溯源 + 飞书风格的中文企业 UX**。
